# ROMFS TODO

## Восстановление после отключения питания

Отложенная задача, обсуждена 2026-09-08. Сначала завершить сквозную обработку
ошибок flash I/O и частичных записей. Схему восстановления реализовывать после
отдельного согласования; пункты ниже — предложение для проработки.

- [ ] Хранить резервные копии `flashmap` и `flashlist` в служебных файлах,
  сохранив основные таблицы по прежним адресам и прежний формат записей ROMFS.
  Каждое поколение должно содержать согласованную пару таблиц. Предпочтительный
  вариант — два заранее выделенных файла, обновляемых по очереди, с возрастающим
  номером поколения в заголовке вместо неограниченного создания новых файлов.
- [ ] Определить заголовок снимка: сигнатура, версия, геометрия файловой системы,
  номер поколения, размеры, контрольная сумма заголовка и таблиц, признак
  завершения. Прерванная запись не должна приниматься за готовое поколение.
- [ ] Обеспечить обнаружение и чтение снимков без исправных основных
  `flashlist`/`flashmap`: например, выделить непрерывные области, обнаруживаемые
  прямым чтением flash по проверяемым заголовкам. Записи служебных файлов должны
  защищать эти области от выделения обычным файлам и от GC. Продумать первое
  включение механизма на существующем образе и нехватку места для резервов.
- [ ] Использовать защиту `SYSTEM | READONLY` и скрывать файлы снимков в
  пользовательских интерфейсах. Отдельного бита `hidden` сейчас нет: все три
  бита режима заняты `READONLY`, `SYSTEM`, `RESERVED`. Не расширять поле атрибутов
  без отдельного решения о совместимости.
- [ ] Проработать порядок фиксации: записать новые данные, записать следующее
  поколение снимка, проверить его чтением, последним записать признак завершения,
  затем обновить основные таблицы. До завершения нового поколения сохранять
  предыдущее. Способ записи признака завершения проверить с учётом ограничений
  erase/program конкретных flash-чипов и существующих callbacks.
- [ ] При загрузке выбирать последнее полностью записанное и проверенное
  поколение и восстанавливать основные таблицы; восстановление должно допускать
  повторное отключение питания. Определить поведение при отсутствии валидных
  снимков, повреждённых заголовках и переполнении номера поколения.
- [ ] Разделить защиту метаданных и данных файлов. Для сохранности данных при
  overwrite, append в неполный сектор и truncate нужна запись изменяемого сектора
  в новое место. Не переиспользовать сектора, необходимые предыдущему поколению,
  до фиксации нового. Одних копий таблиц для восстановления перезаписанных данных
  недостаточно.
- [ ] Определить совместимость со старыми прошивками и host-утилитами. Чтение
  завершённого образа использует прежние основные таблицы. Старые писатели не
  обновляют снимки, поэтому автоматическое восстановление устаревшей копии может
  потерять их изменения. Гарантии восстановления требуют поддержки протокола
  всеми писателями либо явно согласованного ограничения их использования.
- [ ] Добавить тесты прерывания erase/program на каждом этапе, включая частичную
  запись сектора, признак завершения, обновление основных таблиц и восстановление.
  Проверять согласованность таблиц и данных, сохранность предыдущего поколения,
  отсутствие двойного выделения секторов и работу на поддерживаемых геометриях.
